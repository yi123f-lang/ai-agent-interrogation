# AI Agent取調室

AI エージェント（Claude Code）の権限設定 JSON を読み取り、広すぎる許可や危険な設定を日本語で指摘する、簡易静的解析ツールです。

> **ご注意：** このツールは、設定ファイルの文字列を解析するだけの静的解析ツールです。AI エージェントを実際に動かして挙動を確かめたものではなく、実際の Claude Code でのコマンド実行可否を保証するものではありません。

## 解決したい課題

AI エージェントに許可を与える設定（例：`Bash(*)`）は、1行で「任意のシェルコマンドを確認なしで実行してよい」という意味になりえます。また、設定ファイルに API キーなどの認証情報を平文で書いてしまうことや、人による承認を省略するモードを指定してしまうこともあります。

AI Agent取調室は、こうした設定を実行前に洗い出し、次の点を分けて表示します。

- **設定上のリスク**：allow などの記述そのものの危険度
- **現在の実効権限**：deny を考慮した推定（静的解析で判断できない場合は「判定不能」と表示）
- **改善案**

## 実装済みの診断機能（R001〜R005）

| ルール | 検出する設定 | 設定上のリスク | 実効権限の扱い |
|---|---|---|---|
| R001 | `Bash(*)` など、引数パターンがワイルドカード（`*`、`:`、空白）だけの Bash の許可 | 高 | deny による推定（下記） |
| R002 | 引数パターンのない `Bash`、または括弧の中が空の `Bash()` | 高 | deny による推定（下記） |
| R003 | 危険なコマンドへのワイルドカード付きの許可（例：`Bash(rm:*)`、`Bash(curl:*)`） | 高または中（暫定） | deny との文字列照合による推定（下記） |
| R004 | allow／deny の中の、平文の認証情報らしき文字列 | 高 | 判定対象外 |
| R005 | `permissions.defaultMode` による、人による承認の省略 | 高または中 | 常に判定不能 |

1つの設定には、R001〜R003 のうち最初に該当したルールだけを適用します。R004 と R005 は、R001〜R003 とは別に判定します。そのため、同じ設定が R003 と R004 の両方に当てはまる場合は、2件とも表示します。

### R001・R002：deny による実効権限の推定

| deny の状態 | 現在の実効権限 | 総合危険度 |
|---|---|---|
| Bash を制限する deny がない | 有効 | 高 |
| `Bash(rm:*)` など、Bash の一部だけを拒否 | 一部制限 | 高 |
| `Bash(*)`、`Bash`、`*` で全面的に拒否 | 無効（deny により拒否） | 低 |

### R003：危険なコマンドの一覧（暫定）

| コマンド | 設定上のリスク | 対象が限定されている場合 |
|---|---|---|
| `rm` | 高 | 中（`/tmp/…`、`./フォルダー/…` だけを対象にしていると推定できる場合） |
| `sudo`、`python`、`python3`、`bash`、`sh`、`powershell`、`pwsh` | 高 | 下げない |
| `curl`、`wget` | 中 | 低（`https://ホスト/…` だけを対象にしていると推定できる場合） |
| `ssh`、`chmod` | 中 | 下げない |

`..`、`$`、`~` などを含む対象は、限定とはみなしません。コマンド名は、パス、`.exe`、大文字・小文字の違いをそろえてから比べます。

R003 の deny との照合結果は推定です。**deny によって無効と推定された場合でも、総合危険度は下げません。**

| deny の状態 | 現在の実効権限 |
|---|---|
| Bash 全体の拒否、または allow と正規化後の表記が完全に同じ deny | 無効（推定） |
| 同じコマンドに関係しうる deny（例：`Bash(sudo rm:*)`）や、形式を解釈できない deny | 判定不能（要確認） |
| 無関係な deny だけ、または deny なし | 有効（推定） |

### R004：検出する認証情報の形式

次の形式に一致する文字列を検出します。値は表示しません。

- 接頭辞で見分ける形式：`sk-ant-…`、`sk-…`、`ghp_…`、`github_pat_…`、`xox?-…`（Slack）、`AKIA…`（AWS アクセスキー ID）、`AIza…`（Google API キー）
- 値を切り出す形式：`Authorization: Bearer／Basic <値>`、URL の中の `ユーザー:パスワード@`、`api_key=`／`token=`／`secret=`／`password=` などのキーワードの後の値、`--password`／`--token`／`--api-key`／`--secret` の後の値

値を切り出す形式では、次の値はプレースホルダーとして検出しません。

- 8文字未満の値
- `$`、`<`、`*` で始まる値
- `xxx` などの繰り返し
- `your-`／`your_`、`example`、`dummy`、`changeme`、`redacted` で始まる値

allow と deny に同じ設定がある場合は、R004 の指摘を1件にまとめ、両方の場所（例：`permissions.allow[0], permissions.deny[0]`）を表示します。

### R005：人による承認を省略するモード

| `permissions.defaultMode` の値 | 結果 |
|---|---|
| `"bypassPermissions"` | R005（高）。実効権限は判定不能 |
| `"acceptEdits"` | R005（中）。実効権限は判定不能 |
| `"default"`、`"plan"`、キーなし | 指摘しない（設定全体が安全であることを意味するものではありません） |
| 上記以外の文字列、大文字・小文字の違い、文字列以外 | 指摘はせず、値を表示しない警告を出す（安全とはみなしません） |

同じファイルに `disableBypassPermissionsMode: "disable"` があっても、どちらが優先されるかを確認できないため、実効権限は判定不能のままとし、総合危険度は下げません。

## インストールと起動

追加のインストールは不要です。このフォルダーをそのまま使います。

```
interrogation_room/   診断本体（__main__.py、rules.py、report.py、models.py）
tests/                単体テストと CLI テスト
samples/              安全なサンプル設定（認証情報を含みません）
```

プロジェクトのフォルダーで、次のように実行します。

```
python -m interrogation_room <診断する設定ファイル.json>
```

出力をファイルに書き出す場合など、日本語が文字化けするときは `-X utf8` を付けてください。

```
python -X utf8 -m interrogation_room samples/r003_active.json
```

## 診断対象の JSON

引数として、JSON ファイルのパスを1つだけ指定します。

```json
{
  "agent_name": "demo-agent",
  "permissions": {
    "defaultMode": "default",
    "allow": ["Bash(git status)"],
    "deny": []
  }
}
```

| キー | 必須 | 内容 |
|---|---|---|
| `permissions` | 必須 | JSON オブジェクト |
| `permissions.allow` | 必須 | 文字列の配列 |
| `permissions.deny` | 任意 | 文字列の配列（省略時は空） |
| `permissions.defaultMode` | 任意 | R005 で使用 |
| `agent_name` | 任意 | レポートに表示（省略時は「（未設定）」） |

- BOM 付きの UTF-8 も読み込めます。
- 同じキーが重複している JSON は、どちらの値が使われるか曖昧なため、入力エラーとして扱います。
- allow／deny の中の文字列ではない項目や空文字列は、警告を出して検査対象から外します。
- 設定の文字列はコマンドとして実行しません。

## 秘密情報のマスキング仕様

- 認証情報らしき値は、レポートに出す前に `[REDACTED]` に置き換えます。周囲の文字列（例：`--token `）は残します。
- マスクの対象は、設定上の許可、検出根拠に引用する引数パターン、関連 deny（とそれを含む説明文）、警告です。
- R004 の検出根拠には、検出した形式の名前（例：「オプションの値」）と場所だけを書き、値・値の一部・文字数は書きません。
- 判定や重複のまとめには元の値を使い、表示する値だけをマスクします。そのため、マスクによって判定結果は変わりません。
- 入力エラーのメッセージは、JSON の構文エラーの場合、行・列とエラーの種類だけを表示します。

## 診断の限界と既知の問題

### 診断の限界

- 架空の設定 JSON を対象とした静的解析です。AI エージェントを実際に動かした検証ではなく、実際の Claude Code での実行可否は保証しません。
- 複数の設定ファイルの優先順位、起動時の引数、Claude Code のバージョンは考慮していません。
- 設定キーや値の意味（特に R005 の `defaultMode`）は、Claude Code の公式ドキュメントとの照合を行っていません。
- R003 の危険コマンドの一覧と危険度は暫定です。`env rm` などを経由した実行、`&&` などで連結したコマンド、一覧にないコマンドは検出しません。
- R004 は固定のパターン照合です。秘密鍵、8文字未満の値、独自形式のトークン、分割して書かれた値は検出しません。
- R005 は `enableAllProjectMcpServers`、`hooks`、起動時の引数を対象にしていません。

### 既知の問題

- **R005 の表示：** 「設定上の許可」が `"defaultMode: "bypassPermissions""` のように、引用符が二重に表示されます（表示だけの問題で、判定には影響しません）。
- **警告だけの場合の判定：** 指摘が0件で警告だけがある場合（例：`defaultMode` が不明な値）も、判定は「問題なし」になります。警告の内容と判定の表現が食い違います。
- **マスクの範囲：** 引用符で囲まれていない値の直後に `)` などが続く場合、その文字まで `[REDACTED]` に置き換わることがあります（隠しすぎる方向の誤りで、値は表示されません）。
- **判定の文言：** R003 と R005 がともに判定不能の場合は、R003 向けの文言「要確認（deny の効果を判定できない設定があります）」を表示します。
- **重複キーのエラー：** 入力エラーのメッセージに、重複したキーの名前をそのまま表示します。
- **表示の言語：** `--help` の一部（`usage:` など）は英語のままです。
- **画面への直接表示：** PowerShell の画面に直接表示した場合の日本語の表示は、確認していません（ファイルへの書き出しで確認済み）。
